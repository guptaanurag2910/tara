# Tara Database Schema

Schema source: `tara/backend/test.sqlite3`

## Conventions

- `PK` = primary key
- `FK` = foreign key
- `nullable` means the column allows nulls
- Types reflect the SQLite schema generated by Django migrations

## Relationship Summary

- `users_user` is the central table and is referenced by astrology, matching, chat, notifications, games, realtime, and Django auth join tables.
- `astrology_birthdetails` belongs to one user, and `astrology_kundali` belongs to both a user and a birth-details row.
- `users_kundaliprofile` is a separate user-linked kundali/profile store used by the `users` app.
- `matching_match` links two users through `user_a_id` and `user_b_id`.
- `chat_message` belongs to a `matching_match` and a sending user.
- `games_gamesession` belongs to a `matching_match`, a `games_game`, optionally a `games_gamecategory`, and one or two user references.
- `games_gamesessionquestion` links sessions to their selected questions.
- `games_gameresponse` links a user to a question and session, with an optional selected option.
- `realtime_match` and `realtime_message` look like a parallel or older realtime-specific messaging schema alongside `matching_match` and `chat_message`.
